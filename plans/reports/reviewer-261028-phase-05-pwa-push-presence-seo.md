# Review: phase-05 PWA / Push / Presence / SEO (2026-10-28)
tsc --noEmit clean. No critical/security-blocking defects. Ranked:

## Medium
1. **Presence: goOffline race kills new session** - modules/presence/use-player-presence.ts:46-49 and :42. Cleanup (and hidden branch) do `remove().catch().finally(() => goOffline(db))`. goOffline fires after the remove ack (~RTT). If effect re-runs meanwhile (React StrictMode in dev, uid change guest->Google, leaving/re-entering /play quickly) the new effect's `goOnline` (line 30) runs first, then the stale `finally` calls goOffline -> DB offline, presence never written until a visibility toggle. Same for hidden->visible within RTT. Fix: do goOffline synchronously after queuing remove (offline writes still queue? no - so instead) keep a module-level token/counter; in finally only goOffline if token unchanged and still hidden/unmounted. Confidence high (logic), runtime not exercised.
2. **Presence: never written when tab mounts hidden** - same file :34 returns when not visible; visibility->visible only calls goOnline (:41), already online so `.info/connected` does not re-fire. Fix: on visible also run the onDisconnect+set routine directly (factor into `markPresent()`). Confidence high, low impact (background-opened tab).
3. **Cron: one failed delete aborts the run** - server/push/send-daily-reminders.ts:92. `await item.ref.delete()` inside catch can throw; propagates through Promise.all (:102), later chunks never sent, route returns 500. Wrap in try/catch. Confidence high.
4. **Cron: 2000 cap is unordered + spammable** - send-daily-reminders.ts:56 `.limit(2000).get()` without orderBy; docs already sent today (lastSentDay===today) also consume the cap; anonymous Firebase accounts can mint unlimited subscription docs (push-subscription-store.ts:21, no per-uid cap) -> starve real users. Fix: query `where lastSentDay != today`/paginate by cursor until done, cap subscriptions per uid (e.g. 5, delete oldest). Confidence medium-high.
5. **Leaderboard ISR caches empty on transient error** - server/leaderboards/public-leaderboard-tops.ts:23-26 swallows errors and returns empty; with `revalidate=300` (page.tsx:16) the empty HTML replaces the last good page for 5 min (and build without env bakes empty). Fix: rethrow when not build (ISR then keeps stale page), or only swallow at build. Confidence medium.

## Low
6. **SW offline fallback shows /play for every route** - public/sw.js:56 `|| caches.match("/play")`. Offline /profile or /c/{id} gets /play HTML under another URL (Next hydration/route mismatch). Prefer fallback only for SHELL_URLS, else network error / offline page. Confidence medium.
7. **SW caches never pruned** - sw.js:3, :34-43: STATIC_CACHE keeps every old deploy's `_next/static` chunks forever (CACHE_VERSION constant) -> unbounded storage. Stale deploy itself is OK (HTML network-first, hashed chunks). Fix: cap entries or version cache by build id. `cache.put` of 206 responses throws (unhandled rejection, harmless; guard `response.status===200`).
8. **Push subscribe validation shallow** - push-subscription-documents.ts:29: p256dh/auth lengths not checked; bad keys make web-push throw a plain Error each day (counted failed, doc never removed). Also savePushSubscription lets any signed-in uid re-assign an existing endpoint doc (needs knowing the unguessable endpoint; low). Fix: require decoded p256dh 65 bytes / auth 16 bytes; delete docs on non-WebPush validation errors.
9. **notificationclick** - sw.js:101: `existing.navigate()` rejects for uncontrolled/cross-origin client or when payload url origin != SW origin (siteConfig.url vs deployed host) and no fallback -> no window opens. Add `.catch(() => clients.openWindow(target))`; build payload url from request origin/relative path.
10. **VAPID key rotation** - use-push-reminders.ts:87: subscribe throws InvalidStateError if an existing sub used another key; surfaced only as generic toast. Unsubscribe existing then retry.
11. **Presence inflation** - anonymous accounts can write /presence/{uid} unlimited (rules OK per-uid); badge is only social proof, but can hit Spark 100-connection cap. Accept or note.
